# ผลทดสอบโหลด (Load test) — ARCANA PROFILE

ทดสอบเมื่อ 2026-10-20 บนเครื่องพัฒนาของผู้ใช้ (Docker Desktop: 12 CPU, RAM 7.4 GB) ผ่าน http://localhost:8090 (Nginx → Apache/PHP 8.2 + OPcache → MariaDB 11.4)

## วิธีทดสอบ

- จำลองผู้ใช้ส่งคำขอ **ต่อเนื่องไม่หยุดพัก** (ไม่มีช่วงอ่าน/คิด) ระดับละ 15 วินาที — หนักกว่าการใช้งานจริงมาก
- สัดส่วนคำขอแบบห้องเรียนจริง (อ่านอย่างเดียว ไม่แก้ข้อมูล):
  - นักเรียน 80%: แผนที่เควสต์ 40% · โปรไฟล์ 25% · ข้อมูลผู้เล่น 15%
  - ครู 20%: แดชบอร์ดรายวิชา 10% · รายวิชาของฉัน 5% · ไกด์การสอน 5%
- สคริปต์: Node.js `fetch` (อยู่ใน scratchpad ของการพัฒนา ไม่ได้อยู่ในโปรเจกต์)

## ผล

### ก่อนแก้

เปิดการเชื่อมต่อฐานข้อมูลใหม่ทุกคำขอ

| 10 | 1,226 | 7 ms | 15 ms | 0 |
| 25 | 966 | 24 ms | 47 ms | 0 |

| 100 | 572 | 153 ms | 372 ms | **8,579** |

สาเหตุ: `PDOException [2002] Cannot assign requested address`
- ทุกคำขอเปิด TCP ใหม่ไปฐานข้อมูลแล้วปิดทิ้ง
- พอร์ตชั่วคราวใน container หมด จึงเกิด error 500

## แปลผลเป็นจำนวนผู้ใช้

- รองรับได้ประมาณ **2,000 คำขอ/วินาที** และตอบภายใน 0.3 วินาที (p95) แม้มีคำขอค้างพร้อมกัน 300 รายการ
- ผู้ใช้จริงส่งคำขอประมาณ 1 ครั้งทุก 5–10 วินาที (เปลี่ยนหน้า, บันทึกความคืบหน้าเกม)
  - ตัวเซิร์ฟเวอร์จึงรองรับผู้ใช้ออนไลน์พร้อมกัน **หลายพันคน** ในทางทฤษฎี
  - ประเมินแบบเผื่อไว้ **500–1,000 คนพร้อมกัน** ได้สบาย

## ข้อจำกัดที่เป็นคอขวดจริง (ไม่ใช่ตัวระบบ)

1. **Cloudflare Quick Tunnel** (ลิงก์ trycloudflare)
   - เป็นบริการสำหรับทดสอบ จำกัดคำขอที่ค้างพร้อมกันประมาณ 200 รายการ และไม่มีการรับประกัน
   - ใช้งานจริงควรใช้ Named Tunnel หรือเซิร์ฟเวอร์จริง
2. **ความเร็วอัปโหลดอินเทอร์เน็ตของเครื่องที่รันระบบ**
   - ภาพเกม (ตัวละคร/ฉาก) โหลดครั้งแรกหลาย MB ต่อคน
   - ถ้าทั้งห้อง 40 คนเปิดพร้อมกัน ช่วงแรกอาจช้าตามความเร็วอัปโหลด หลังจากนั้นเบราว์เซอร์จะ cache ไว้
3. **ยังไม่ได้ทดสอบการเขียนข้อมูลจำนวนมาก** เช่น นักเรียนบันทึกความคืบหน้าพร้อมกัน
   - ทดสอบเฉพาะการอ่าน เพราะเป็นฐานข้อมูลจริง
   - การเขียนแต่ละครั้งเล็กมาก (1 แถว) คาดว่าไม่เป็นปัญหาที่ระดับห้องเรียน
4. **AI (Gemini)**
   - ไม่ได้ขึ้นกับเซิร์ฟเวอร์ของเรา แต่ขึ้นกับโควตา API Key ของครูแต่ละคน และความพร้อมของ Google
5. **เครื่องเดียว**
   - ถ้าเครื่องปิดหรือ Sleep ระบบหยุดทั้งหมด
   - ใช้งานจริงทั้งวิทยาลัยควรย้ายขึ้นเซิร์ฟเวอร์ที่เปิดตลอด (ดู [DEPLOY.md](DEPLOY.md))
