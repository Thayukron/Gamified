# เอกสารข้อกำหนดความต้องการระบบ (System Requirements Specification)
**ชื่อโครงการ:** ระบบประเมินโปรไฟล์ผู้เรียนอัจฉริยะผ่านเกมจำลองสถานการณ์ (Gamified Universal Student Profiling System)[cite: 1, 3, 4]
**แนวคิดหลัก:** เล่นเกมเพื่อค้นหาตัวตน วิเคราะห์ผลด้วย Logic ประมวลผลคำแนะนำด้วย AI (Zero API Cost during Gameplay)[cite: 3]
**สถาปัตยกรรมระบบ (Two-Tier Assessment):**
*   **ระดับแกนกลาง (Core Profile):** สร้างเกมจำลองสถานการณ์มาตรฐานกลางเพื่อวัด VARK, RIASEC และ Mindset โดยผู้เรียนทดสอบเพียง 1 ครั้งต่อภาคเรียน[cite: 4]
*   **ระดับประยุกต์ใช้ (Contextual Analytics):** ใช้ AI ช่วยประมวลผลบนแดชบอร์ดครู เพื่อแปรผลลัพธ์ให้เข้ากับบริบทเฉพาะของแต่ละรายวิชา[cite: 4]

## 1. กลุ่มผู้ใช้งานระบบ (User Roles)
*   **ผู้เรียน (Student):** เข้าเล่นเกมจำลองสถานการณ์ ดูประวัติการเล่น และรับการ์ดสรุปโปรไฟล์ (Archetype Card) ของตนเอง[cite: 1, 3]
*   **ครูผู้สอน (Teacher):** ดูแดชบอร์ดสรุปผลของนักศึกษาในกลุ่มเรียนของตน ใช้ปุ่ม AI วิเคราะห์แผนการสอน และสร้างเนื้อเรื่องเกมใหม่[cite: 1, 3]
*   **ผู้ดูแลระบบ (System Admin):** บริหารจัดการข้อมูลรายวิชา แผนกวิชา จัดการ API Key และดูแลชุดเนื้อเรื่องสากล[cite: 1, 3]

## 2. ความต้องการทางฟังก์ชัน (Functional Requirements)
*   **โมดูลฝั่งผู้เรียน (Game Engine & Profiling):**
    *   เข้าสู่ระบบและแสดงรายการเควสต์ (Quest Selection)[cite: 3] โดยระบบจะตรวจสอบสถานะว่าเคยเล่นแล้วหรือไม่[cite: 2]
    *   แสดงผลรูปแบบ Visual Novel รองรับภาพพื้นหลัง แอนิเมชัน (เช่น Typewriter Effect, Screen Shake, Fade) และระบบเสียง[cite: 1, 4]
    *   บันทึกการตัดสินใจแบบ Real-time และรองรับการทำ Save State กรณีออกกลางคัน[cite: 1, 3]
    *   คำนวณคะแนนเบื้องหลัง (Tagging) ด้วย Rule-based 100%[cite: 2, 3]
    *   แสดงหน้าจอสรุปผลเป็นการ์ดตัวละคร (Archetype Profile Card) พร้อมคำอธิบายเชิงบวก[cite: 1, 3]
*   **โมดูลฝั่งครู (Scenario Builder & Content Management):**
    *   มีคลังเนื้อเรื่อง (Story Library) ส่วนกลางให้ครูคัดลอกไปใช้ได้ทันที[cite: 1, 3]
    *   มีหน้า UI ให้ครูหรือแอดมินสร้าง Scene และ Choices พร้อมผูกค่าคะแนนคุณลักษณะ[cite: 1, 3]
    *   แปลงข้อมูลเนื้อเรื่องที่สร้างขึ้นเป็นไฟล์ JSON อัตโนมัติ[cite: 1]
    *   เครื่องมือ AI Story Generator สำหรับช่วยร่างเนื้อเรื่องและตัวเลือกผ่านการพิมพ์ Prompt[cite: 3]
*   **โมดูลแดชบอร์ด (Smart Analytics Dashboard):**
    *   แสดงกราฟสรุปสัดส่วน (Pie Chart/Bar Chart) ของรูปแบบการเรียนรู้และความสนใจระดับห้องเรียน[cite: 1, 2, 3]
    *   แสดงโปรไฟล์เชิงลึกรายบุคคลด้วยกราฟใยแมงมุม (Radar Chart)[cite: 1, 3]
    *   ฟังก์ชัน Contextual AI Prompting เพื่อสร้างคำแนะนำการจัดการเรียนการสอนเฉพาะห้องเรียน พร้อมระบบ Caching[cite: 2, 3, 4]
    *   ส่งออกรายงานเป็น PDF/Excel เพื่อใช้ประกอบการประเมิน ว.PA หรือวิจัยชั้นเรียน[cite: 1, 2, 3]
*   **โมดูลการจัดการ (Core Management):**
    *   นำเข้าข้อมูลนักศึกษาและการจัดกลุ่มเรียนผ่านไฟล์ CSV/Excel[cite: 1, 3]
    *   ตั้งค่าระบบและ API Key ของ AI สำหรับเปิด/ปิดฟังก์ชัน (BYOK)[cite: 3]

## 3. ความต้องการนอกเหนือฟังก์ชันและเทคโนโลยี (NFR & Tech Stack)
*   **User Experience:** ฝั่งผู้เรียนต้องทำงานเป็น Progressive Web App (PWA) บนมือถือ ส่วนฝั่งครูออกแบบให้ใช้งานง่ายบนคอมพิวเตอร์ Desktop[cite: 1, 3]
*   **Performance:** รองรับนักศึกษาใช้งานพร้อมกันอย่างน้อย 500-1000 คน โดยการประมวลผลคะแนนเกิดขึ้นฝั่งระบบจัดการหลังบ้านหรือ Rule-based ทันที[cite: 1, 3]
*   **Technology Stack:**
    *   **Frontend:** Vue.js 3 / Nuxt 3 จัดการ State ด้วย Pinia และปรับแต่ง UI ด้วย Tailwind CSS[cite: 1, 2, 3]
    *   **Backend & Database:** PHP (RESTful API), MySQL[cite: 1, 2, 3]
    *   **Libraries:** Chart.js หรือ ApexCharts (กราฟแสดงผล), html2pdf.js หรือ mPDF (ส่งออกรายงาน PDF)[cite: 2]

## 4. โครงสร้างฐานข้อมูล (Database Schema)
*   `users`: เก็บข้อมูลผู้ใช้งาน รหัสผ่าน และแผนกวิชา[cite: 2, 3]
*   `courses`: เก็บข้อมูลรายวิชาและข้อมูลครูผู้สอน[cite: 2, 3]
*   `enrollments`: ตารางเชื่อมโยงการลงทะเบียนเรียนระหว่างนักศึกษากับรายวิชา[cite: 2, 3]
*   `scenarios`: เก็บข้อมูลคลังเนื้อเรื่องหลัก และเก็บโครงสร้างฉากทั้งหมดเป็นรูปแบบ JSON[cite: 2, 3]
*   `archetype_master`: เก็บข้อมูลการ์ดตัวละครและรายละเอียดจุดแข็ง[cite: 2]
*   `assessment_results`: เก็บผลลัพธ์คะแนนรวมทุกหมวด และผลการ์ดตัวละครที่ได้รับ[cite: 2, 3]
*   `ai_insights_cache`: เก็บคำแนะนำการสอนที่ AI ประมวลผลไว้[cite: 2, 3]

## 5. เส้นทางการใช้งานระบบ (User Journey)
*   **การเตรียมระบบ:** ส่วนกลางนำเข้าข้อมูล และกำหนดเปิดใช้งานชุดเนื้อเรื่องเกมสากล[cite: 4]
*   **ประสบการณ์ผู้เรียน:** ล็อกอินเข้าเล่นเกมในคาบแรก รับการ์ดสรุปตัวละคร และสามารถบันทึกหรือแชร์ผลลัพธ์ได้ทันที[cite: 4]
*   **ประสบการณ์ครูผู้สอน:** ตรวจสอบสัดส่วนผู้เรียนในห้องเรียน ขอคำแนะนำจาก AI ตามบริบทรายวิชาของตน นำข้อมูลไปใช้จัดกลุ่มทำงานอัจฉริยะ และส่งออกรายงานสำหรับการประเมิน ว.PA[cite: 4]
